01Overview概述

The Inventory Dashboard is a role-based web application for tracking consumable inventory — spare parts, lubricants, PPE, and similar stock-keeping items — across a facility. It supports:

  • Searching, filtering, and paginating inventory items
  • Adding / editing items: SKU, quantity, thresholds, category, unit of measure, bin location, production/expiry dates, specification, and a photo
  • Storing item photos
  • Export to CSV or XLSX
  • Role-based user management (admin / editor / viewer)
  • Managing reference data: categories and units
  • App-wide settings (currently the company name)

The entire stack runs on Cloudflare free-tier services, so ongoing cost is ~$0/month for light internal use.

库存仪表盘（Inventory Dashboard）是一款基于角色的 Web 应用，用于管理一个厂区内的可消耗库存（备件、润滑油、劳保用品等）。其核心能力包括：

  • 对库存条目进行搜索、筛选与分页浏览
  • 新增 / 编辑条目：SKU、数量、阈值、类别、计量单位、货位、生产/到期日期、规格、照片
  • 条目图片的存储
  • 导出 CSV 或 XLSX
  • 基于角色的用户管理（管理员 / 编辑 / 查看）
  • 参考数据管理：类别 与 单位
  • 应用级设置（目前为：公司名称）

整个技术栈运行在 Cloudflare 免费额度内，轻度内部使用下持续成本约为 $0/月。

Key design decisions关键设计决策

  • D1, not Turso. The current system uses Cloudflare D1. (Earlier drafts describing a Turso + read-only + no-auth design are obsolete.)
  • UUID primary keys. No rowId / auto-increment; IDs are generated server-side with crypto.randomUUID() and are strings — never parse them as integers.
  • Units denormalized by name. consumable_item.unit stores the unit's name (TEXT), the same pattern as category. Deleting a unit is blocked while any item references it.
  • Tigris has no object ACLs. Images are served through the same-origin proxy GET /api/images/{key} so the SPA's CSP (img-src 'self' data: blob:) can load them.
  • No auto-migrations. Schema changes are SQL files in migrations/, applied manually to remote D1 (§7.3).
  • 使用 D1，而非 Turso。 当前系统采用 Cloudflare D1。（早期草稿中“Turso + 只读 + 无鉴权”的方案已作废。）
  • UUID 主键。 无 rowId / 自增；ID 在服务端用 crypto.randomUUID() 生成，是字符串——切勿按整数解析。
  • 单位按名称去规范化。 consumable_item.unit 存储单位的名称（TEXT），与 category 相同；只要有条目引用，该单位即不可删除。
  • Tigris 无对象 ACL。 图片通过同源代理 GET /api/images/{key} 提供，使 SPA 的 CSP（img-src 'self' data: blob:）能加载它们。
  • 无自动迁移。 结构变更是 migrations/ 下的 SQL 文件，手动应用到远端 D1（§7.3）。

05Authentication & sessions认证与会话策略

Tokens令牌

  • Access token: JWT, HS256, 8-hour lifetime, delivered in the auth_token cookie. (The file header in functions/lib/auth.ts still says "15-minute" — that comment is stale; the code is ACCESS_TOKEN_TTL_MS = 8*60*60*1000.)
  • Refresh token: opaque, 7-day lifetime, stored in D1 refresh_tokens, delivered in the refresh_token cookie. Rotated on every refresh (the used token is deleted, a new one stored).
  • Cookies: HttpOnly; Secure; SameSite=Strict; Path=/.
  • 访问令牌： JWT，HS256，8 小时有效期，经 auth_token Cookie 下发。（functions/lib/auth.ts 文件头仍写“15 分钟”——注释已过时；代码为 ACCESS_TOKEN_TTL_MS = 8*60*60*1000。）
  • 刷新令牌： 不透明，7 天有效期，存于 D1 refresh_tokens，经 refresh_token Cookie 下发。每次刷新都轮转（删除旧令牌、写入新令牌）。
  • Cookie 属性：HttpOnly; Secure; SameSite=Strict; Path=/。

Passwords密码

  • Hashed with PBKDF2-SHA256, 100,000 iterations, 16-byte salt, stored as base64(salt):base64(hash).
  • Policy: 8–128 characters, at least one letter and one number.
  • New / reset passwords are checked against a breach list (HIBP k-anonymity) and rejected if too common.
  • 使用 PBKDF2-SHA256、100,000 次迭代、16 字节盐 哈希，存储格式 base64(salt):base64(hash)。
  • 策略：8–128 字符，至少含一个字母和一个数字。
  • 新建/重置密码先经泄露库（HIBP k-匿名）校验，过于常见的密码被拒绝。

06User flows用户流程

Loading the app

src/main.tsx mounts Root, which calls GET /api/users/me on start: 200 → dashboard (App.tsx); 401 / error → login page.

Logging in

Enter username + password → POST /api/auth/login. On success the server sets both cookies and the app reloads into the dashboard. A wrong/unknown credential returns a uniform "Invalid username or password" (no user enumeration).

Dashboard

Four stat cards (Total / Low Stock / Out of Stock / Expiring Soon), a Filters row (search, category, status, view + Reset), an Export button (CSV / XLSX of the current filter), and the inventory table with pagination (10 / 25 / 50 / 100 per page). The quantity cell shows the value plus its unit, e.g. 12 L.

Edit / add item

The Add / pencil button opens the edit modal: SKU (locked on edit), Name, Category, Unit (managed list, with a (legacy) option for values not in the list), quantity + min/max thresholds, bin location, production/expiry dates, specification, description, and an image preview (remove via the 🗑 button).

Images

Editors can upload (camera icon), view (click thumbnail → lightbox), or remove an item photo. Uploads go to Tigris and are read back through the /api/images/{key} proxy.

Admin panels (header, role-gated)

  • Users (admin): create / edit / lock / delete users.
  • Categories (editor+): add / rename / delete (delete admin-only, in-use guarded).
  • Units (editor+): add / rename / delete (delete admin-only, in-use guarded).
  • Settings (admin): edit company_name.

Logging out & silent refresh

POST /api/auth/logout revokes the refresh token and clears both cookies. If a data request returns 401, the app first tries POST /api/auth/refresh (using the refresh cookie) and retries; only if that also fails does it force a logout. This keeps sessions alive within the 7-day refresh window.

加载应用

src/main.tsx 挂载 Root，启动时调用 GET /api/users/me：200 → 仪表盘（App.tsx）；401 / 异常 → 登录页。

登录

输入用户名 + 密码 → POST /api/auth/login。成功后服务端写入两个 Cookie，应用重载进入仪表盘。用户名或密码错误时统一返回 "Invalid username or password"（不泄露账号是否存在）。

仪表盘

四张统计卡（总数 / 低库存 / 缺货 / 即将到期）、筛选行（搜索、类别、状态、视图 + 重置）、导出按钮（按当前筛选导出 CSV / XLSX），以及带分页（每页 10 / 25 / 50 / 100）的库存表格。数量列显示数值加单位，例如 12 L。

编辑 / 新增条目

Add / 铅笔按钮打开编辑弹窗：SKU（编辑时锁定）、名称、类别、单位（受管列表，对不在列表中的旧值提供 (legacy) 选项）、数量与最小/最大阈值、货位、生产/到期日期、规格、描述，以及图片预览（可点 🗑 移除）。

图片

编辑者可上传（相机图标）、查看（点击缩略图 → 灯箱）、移除条目照片。图片上传到 Tigris，并经 /api/images/{key} 代理读取。

管理面板（页头，按角色显示）

  • 用户（admin）：新建 / 编辑 / 锁定 / 删除用户。
  • 类别（editor+）：新增 / 重命名 / 删除（删除仅 admin，使用中受保护）。
  • 单位（editor+）：新增 / 重命名 / 删除（删除仅 admin，使用中受保护）。
  • 设置（admin）：编辑 company_name。

退出与静默刷新

POST /api/auth/logout 吊销刷新令牌并清除两个 Cookie。若某数据请求返回 401，应用先尝试 POST /api/auth/refresh（用 refresh Cookie）并重试；只有它也失败时才强制登出。这让 7 天刷新窗口内的长会话保持有效。

08Security policy安全策略

  • Response headers (applied by functions/_middleware.ts on every response): a strict same-origin Content-Security-Policy (default-src 'self'; img-src 'self' data: blob: — images load only via the same-origin /api/images/ proxy plus client-side data:/blob: compression), X-Frame-Options: DENY, X-Content-Type-Options: nosniff, Referrer-Policy: strict-origin-when-cross-origin, Permissions-Policy (camera / microphone / geolocation disabled), and Strict-Transport-Security (1 year, includeSubDomains).
  • Secrets — operational secrets (AUTH_SECRET, Tigris keys) are never committed, never in the docs, and never returned by the API. The deliberate exception is the demo / first-run credential (admin / Admin@2024!), which is documented so the project can be evaluated; it is not an operational secret and must be rotated for any real deployment.
  • Default credential: a seeded admin account ships for demo / evaluation only. It is public by design — treat it as invalid in production: change the password, set a strong AUTH_SECRET, and delete the account.
  • Least-privilege roles (§5); destructive actions (delete item / category / unit, user & settings management) are admin-only.
  • In-use guards prevent deleting a category or unit that items still reference.
  • Rate limiting (§5.3) throttles login, inventory, and upload abuse.
  • Cred-leak history: the Tigris keys that appeared in an earlier document are revoked and must not reappear — if a real operational secret surfaces again, treat it as compromised and rotate immediately. The seeded admin demo credential is a separate, deliberate value, not a leak.
  • 响应头（由 functions/_middleware.ts 对每个响应统一设置）：严格的同源 Content-Security-Policy（default-src 'self'；img-src 'self' data: blob:——图片只经由同源的 /api/images/ 代理、以及 data:/blob: 客户端压缩图加载）、X-Frame-Options: DENY、X-Content-Type-Options: nosniff、Referrer-Policy: strict-origin-when-cross-origin、Permissions-Policy（禁用摄像头 / 麦克风 / 地理位置）、以及 Strict-Transport-Security（1 年，includeSubDomains）。
  • 密钥 —— 运行密钥（AUTH_SECRET、Tigris 密钥）从不提交、不写入文档、也不由 API 返回。唯一的例外是演示 / 首启凭据（admin / Admin@2024!），它被刻意记录在文档中以便评估；它不是运行密钥，真实部署必须轮换。
  • 默认凭据：内置 admin 账号仅用于演示 / 评估。它按设计是公开的——生产环境视为无效：请改密、设置强 AUTH_SECRET，并删除该账号。
  • 最小权限角色（§5）；破坏性操作（删除条目 / 类别 / 单位、用户与设置管理）仅 admin。
  • 使用保护防止删除仍被条目引用的类别或单位。
  • 限流（§5.3）抑制登录、库存、上传的滥用。
  • 密钥泄露历史：早前文档中出现过的 Tigris 密钥已被吊销，不得再次出现——若真实的运行密钥再次出现，一律视为已泄露并立即轮换。内置的 admin 演示凭据是另当别论的刻意公开值，不属于泄露。
